# 🛡️ Git Hygiene & Repository Best Practices

**Objetivo:** Evitar que artifacts, secrets e arquivos temporários sejam commitados novamente.

---

## 🎯 Core Rules

### 1. The Golden .gitignore Rule

**Princípio:** Se um arquivo é gerado automaticamente, local-only, ou usado durante desenvolvimento, deve estar em `.gitignore`.

```
✅ SHOULD BE IGNORED:
  - node_modules/              (generated by npm/pnpm)
  - .next/                     (generated by Next.js build)
  - dist/, build/              (generated by build tools)
  - *.log                       (logs, never needed)
  - .env.local                 (secrets)
  - .DS_Store, Thumbs.db       (OS files)
  - .clauderules, .cursorrules (IDE/agent configs)
  - .superpowers/              (AI brainstorm cache)
  - scratch/                   (debug scripts)
  - omnirepo.db*               (database files)

❌ SHOULD NOT BE IGNORED:
  - .env.example               (template, safe to share)
  - package.json, pnpm-lock.yaml (lock files needed)
  - src/, lib/, app/           (source code)
  - .github/workflows/         (CI/CD config)
  - supabase/migrations/       (schema changes)
  - README.md, docs/           (documentation)
```

### 2. Before Committing: Check What You're Adding

```bash
# Review staged changes
git add file.ts
git diff --staged           # See exactly what you're adding

# If something sneaks in:
git reset HEAD unwanted.js  # Unstage it
echo "unwanted.js" >> .gitignore
git add .gitignore
```

### 3. Migrations NOT Backups

```
✅ CORRECT SCHEMA VERSIONING:
   supabase/migrations/
   ├── 001_init.sql         ← Applied sequentially to build schema
   ├── 002_users.sql
   ├── 003_leads.sql
   └── 070_optimize_rls.sql

❌ WRONG — Don't Do This:
   supabase/
   ├── schema.sql           ← Full dump (confusing)
   ├── schema_v2.sql        ← Backup (don't commit)
   ├── fix_rls.sql          ← One-off fix (use migration instead)
   └── migrations/          ← Actual migrations

RULE: If you need to fix the schema, CREATE A MIGRATION.
      Don't commit backup files.
```

### 4. Debug Scripts Local-Only

```bash
# ✅ DO THIS:
cat > scratch/debug_query.js << 'EOF'
const { createClient } = require('@supabase/supabase-js');
// Your debug code
EOF
node scratch/debug_query.js
rm scratch/debug_query.js

# ❌ DON'T DO THIS:
git add scratch/debug_query.js
git commit -m "debug: temp script"  # Never!
```

## 🔒 Security Rules

### 1. Never Hardcode Secrets

```typescript
// ❌ NEVER:
const STRIPE_SECRET = "sk_live_abc123...";
const API_KEY = "Bearer xyz789...";

// ✅ ALWAYS:
const STRIPE_SECRET = process.env.STRIPE_SECRET_KEY;
const API_KEY = process.env.API_KEY;
```

### 2. Rotate Secrets If Accidentally Exposed

Even if you remove a file from git:
```bash
# Git stores entire history
git log --all --diff-filter=D -- file.env | head -5

# If you ever committed a secret, even deleted:
# 1. Rotate the secret immediately
# 2. Remove from git history (git filter-repo)
# 3. Force push
```

### 3. Use .env.example as Safe Template

```bash
# ✅ DO THIS:
.env.example     ← Public, shows structure
.env.local       ← Private, in .gitignore, has real values

# ✅ For Team/CI:
.env.example     ← Public template
.env.production  ← In Vercel/GitHub Secrets (NOT in repo)
```

### 4. Pre-commit Hooks (Optional But Recommended)

Install Husky:
```bash
pnpm add -D husky
pnpm husky install
pnpm husky add .husky/pre-commit "npm run lint"
```

Add secret detection:
```bash
# .husky/pre-commit
#!/bin/sh

# Prevent secrets
if git diff --cached --name-only | grep -E '\.env|.credentials|keys.json'; then
  echo "❌ Blocked: .env or credential files in commit"
  exit 1
fi

# Prevent agent artifacts
if git diff --cached --name-only | grep -E '\.clauderules|\.cursorrules|\.superpowers'; then
  echo "❌ Blocked: Agent/IDE config files should be .gitignored"
  exit 1
fi

exit 0
```

## 📋 Agendra-Specific Rules

From `CLAUDE.md` and audit findings:

### 1. Agent Rules Files

```
✅ Create locally: .clauderules, .cursorrules
✅ Use in your IDE
❌ Never commit
✅ Add to .gitignore (already there)
```

### 2. Supabase Migrations

```
✅ CREATE NEW MIGRATION for schema changes:
   supabase/migrations/071_my_change.sql

❌ Don't commit:
   supabase/schema_v*.sql    (backups)
   supabase/fix_*.sql        (one-off fixes)
```

### 3. Debug/Scratch Scripts

```
✅ Create in scratch/ for local testing
✅ They're .gitignored
❌ Never add scratch/*.js to git
❌ Delete after testing

Example:
cat > scratch/test_query.ts << 'EOF'
// test code
EOF
tsx scratch/test_query.ts
rm scratch/test_query.ts  # Always clean up
```

### 4. Environment Variables

```
✅ .env.example in repo (public, no values)
❌ .env.local NOT in repo (private, has values)
❌ .env.production NOT in repo (use Vercel Secrets)

NEVER:
- Commit any .env file with real values
- Hardcode API keys in code
- Share credentials in comments
```

## 🚀 GitHub Actions Check

Add to `.github/workflows/ci.yml` to prevent regressions:

```yaml
name: Repository Hygiene Check

on: [push, pull_request]

jobs:
  hygiene:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Check for unintended artifacts
        run: |
          # Fail if tracked files match problematic patterns
          ARTIFACTS=$(git ls-files | grep -E '\.clauderules|\.cursorrules|\.superpowers|scratch/.*\.(js|ts)$|supabase/(schema_v|fix_rls)' || true)
          
          if [ -n "$ARTIFACTS" ]; then
            echo "❌ Development artifacts found in git:"
            echo "$ARTIFACTS"
            exit 1
          fi
          
          echo "✅ No development artifacts in git"

      - name: Check for secrets
        run: |
          # Simple check for common secret patterns
          if git log -p -n 20 | grep -E 'sk_live|sk_test|Bearer|password.*:'; then
            echo "⚠️ Potential secrets found in recent commits"
            echo "Review and rotate if necessary"
            # Note: This is basic — use truffleHog or similar for production
          fi
```

## 📚 Quick Reference Card

```
┌─────────────────────────────────────────────────────────────┐
│ BEFORE COMMITTING ALWAYS ASK:                               │
├─────────────────────────────────────────────────────────────┤
│ ☐ Does this file have secrets or credentials?              │
│ ☐ Is this file generated by tools (build/cache)?          │
│ ☐ Is this file local-only (IDE config, debug script)?     │
│ ☐ Is this a backup of existing versioned data?            │
│ ☐ Does git diff --staged show what I expect?              │
│                                                               │
│ If YES to any above → DON'T COMMIT IT                       │
│ Add to .gitignore instead                                    │
└─────────────────────────────────────────────────────────────┘

GOLDEN RULES:
  1. Source code IN   → .gitignore exclusions
  2. Secrets OUT      → .env* and .gitignore
  3. Debug local      → scratch/ only
  4. Migrations yes   → Backups no
  5. When in doubt    → Ask before committing
```
